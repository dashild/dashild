El shell vive en `@dashild/admin`; la app es dueña de la configuración del
panel, la autenticación y los componentes propios.

## Panel

```ts
// src/dashild/panel.ts
import { definePanel } from "@dashild/core";

export const panel = definePanel({
  title: "Acme",
  path: "/admin",
  locale: "en",
  brand: { name: "Acme" },
  theme: { defaultMode: "dark", toggle: true, primary: "zinc" },
  sidebar: { collapsible: "icon" },
  maxContentWidth: "xl",
  resources: [customerResource],
  auth: { getCurrentUser, signOut },
});
```

`primary` acepta una paleta de shadcn/Tailwind (`zinc`, `slate`, `blue`,
`emerald`, etc.). `locale` cambia las etiquetas integradas, los mensajes de
validación del servidor y los mensajes del formulario en el navegador.
`theme.defaultMode` acepta `light`, `dark` o `system`; `system` sigue
`prefers-color-scheme` y reacciona a los cambios.

`brand.logo` sustituye la marca del panel en la barra lateral. Sin logo, el
shell dibuja la marca de Dashild, que hereda el color de texto del tema.
`brand.name` se acepta en los metadatos del panel, pero las páginas de acceso
generadas todavía no lo muestran. `domain` es metadata declarada y nada más:
Next enruta por host, así que Dashild no lo usa para enrutar peticiones.

### Conmutador de tema

`theme.toggle: true` muestra el conmutador solo si la ruta pasa también una
server action `themeAction`. La ruta que genera `dashild init` ya la cablea: lee
la cookie `dashild_theme` para el modo inicial y pasa `toggleTheme`, que alterna
`light` → `dark` → `system` y escribe la cookie.

En una instalación manual sin ese cableado, el conmutador se oculta. Añade una
acción como la generada y pásala a `AdminPage`:

```tsx
// src/app/admin/[[...dashild]]/page.tsx
const store = await cookies();
const cookieTheme = store.get("dashild_theme")?.value;
const theme: ThemeMode =
  cookieTheme === "light" || cookieTheme === "dark" || cookieTheme === "system"
    ? cookieTheme
    : panel.theme?.defaultMode ?? DEFAULT_THEME_MODE;

<AdminPage
  // ...
  theme={theme}
  themeToggle={panel.theme?.toggle ?? false}
  themeAction={toggleTheme}
/>;
```

`DEFAULT_THEME_MODE` es `dark`. Con `system`, el servidor no puede conocer la
preferencia del usuario, así que la clase `dark` se aplica en el cliente tras
hidratar.

## Celdas y campos

Las celdas y los campos son componentes React registrados en el cliente:

```tsx
// src/dashild/registry.tsx
"use client";

import {
  registerCell,
  registerField,
  registeredCells,
  registeredFields,
} from "@dashild/core";
import { RegistryProvider, type Registry } from "@dashild/admin";

import { AvatarCell } from "../../components/dashild/avatar-cell";
import { EmailField } from "../../components/dashild/email-field";

registerCell("avatar", AvatarCell);
registerField("email", EmailField);

export function AppRegistryProvider({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <RegistryProvider
      cells={registeredCells() as Registry["cells"]}
      fields={registeredFields() as Registry["fields"]}
    >
      {children}
    </RegistryProvider>
  );
}
```

Los casts son necesarios: `registeredCells()` devuelve el tipo laxo que guarda
`@dashild/core` para no depender de los tipos de React.

`dashild init` genera este fichero con las llamadas de registro comentadas;
edítalo para añadir las tuyas. Envuelve `AdminPage` con `AppRegistryProvider`
(la ruta generada lo hace) y referencia los componentes desde un recurso:

```ts
table: { columns: [{ field: "name", cell: "avatar" }] }
form: { fields: [{ field: "email", component: "email" }] }
```

Las props de los renderers son `CellRendererProps` y `FieldRendererProps` de
`@dashild/admin`.

`dashild ui:add avatar-cell email-field` copia ambas plantillas a
`components/dashild/` e imprime la llamada de registro exacta, por ejemplo
`registerCell("avatar", AvatarCell)`. Opciones: `--dir`, `--force`,
`--dry-run`, `--cwd`. Los nombres desconocidos se avisan y no cambian el código
de salida.

## Tailwind

Tailwind debe escanear el build del paquete:

```css
@source "../../node_modules/@dashild/admin/dist";
```

Las variables de tema vienen de shadcn. Define una pila de fuentes real en
`--font-sans`; el `globals.css` generado lo hace por ti.

## Iconos

El shell ya resuelve 19 nombres: `users`, `user`, `building`, `organization`,
`file-text`, `settings`, `database`, `folder`, `chart`, `layout-dashboard`,
`package`, `shopping-cart`, `tag`, `calendar`, `mail`, `briefcase`,
`credit-card`, `truck` y `layers`.

`src/dashild/icons.tsx` monta un `IconProvider` que añade **tus** iconos extra;
no sustituye el conjunto integrado. Para un icono de recurso desconocido el
shell cae siempre en un icono genérico de tabla, y avisa solo en desarrollo. Los
iconos de acción no tienen fallback: un nombre desconocido no renderiza icono.

## Eject

Si quieres quitar el glue del panel:

```bash
pnpm dashild eject --dry-run
pnpm dashild eject --yes
```

Elimina `panel.ts`, `policies.ts`, `actions/index.ts`, `icons.tsx`,
`runtime.ts`, `server.ts`, `registry.tsx`, la ruta de montaje y el script
`dashild`. Conserva los recursos, los ficheros de auth, el generador de Prisma y
las dependencias, y lista los que puede detectar. Algunos ficheros de auth
(`email.ts`, las páginas y formularios de contraseña) se conservan pero no se
listan. Sin `--yes` solo imprime el plan.

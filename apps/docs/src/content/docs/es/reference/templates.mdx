`create-dashild` incluye dos starters:

- `basic`: sin ficheros extra. El dashboard muestra el estado vacío; con el
  `--auth better-auth` por defecto también tienes login, signup y reset.
- `demo`: usuarios, posts y etiquetas, con políticas de demo permisivas y un
  seed (`ana@acme.test` / `dashild123`).

```bash
pnpm create dashild@latest mi-app --template demo
```

Un starter también puede ser una carpeta local o venir de GitHub:

```bash
npx create-dashild@latest mi-app --template ./starters/crm
npx create-dashild@latest mi-app --template local:../starters/crm
npx create-dashild@latest mi-app --template github:acme/dashild-crm#main
```

Las plantillas de npm no están soportadas en la alpha actual. El valor de
`--template` es una ruta local (`./...`, una ruta absoluta o `local:<ruta>`) o
un spec `github:`.

## Formato

Una plantilla es una carpeta con `template.json` y ficheros del proyecto:

```json
{
  "name": "crm",
  "version": "1.0.0",
  "dashild": ">=0.1.0-alpha.8",
  "prisma": { "provider": ["postgresql"] },
  "requires": { "auth": ["better-auth"] },
  "extend": { "User": ["role Role @default(USER)"] },
  "env": ["STRIPE_SECRET"]
}
```

| Campo | Para qué |
| --- | --- |
| `name`, `version` | Identidad registrada en `dashild.json`. |
| `dashild` | Rango semver de Dashild soportado. |
| `prisma.provider` | Proveedores de base de datos permitidos. |
| `requires.auth` | Integración de auth requerida (array). |
| `extend` | Campos Prisma extra para un modelo existente. |
| `dependencies`, `devDependencies` | Dependencias extra de la app. |
| `env` | Claves de entorno añadidas a `.env.example` si faltan. |

## Ficheros

- `prisma/models.prisma` se añade al esquema dentro de un bloque con marcador.
  Si la misma plantilla se aplica otra vez, el comando falla con “already
  applied” en lugar de duplicar modelos. El marcador detecta la reaplicación; no
  la hace idempotente.
- `extend` añade campos a modelos que ya existen (por ejemplo `User`). Los
  campos que ya están presentes se omiten en silencio.
- Un modelo o enum cuyo nombre ya existe en el esquema es un error duro.
- `src/dashild/resources/*.ts` se copian y se registran en `panel.ts`.
- `src/dashild/policies.ts` sustituye las políticas por defecto.
- `prisma/seed.ts` se ejecuta solo si los pasos de instalación y migración
  terminaron bien; con `--seed` pero sin migración queda pendiente.
- Las claves de `env` se añaden a `.env.example` con valor vacío; los valores
  los pones tú.

Las plantillas se aplican después de crear los modelos de Better Auth, así que
una plantilla puede extender `User` sin riesgo.

## Fijado de paquetes

`dashild.json` registra la plantilla elegida, la auth, la base de datos, la ruta
y la fecha de creación. No guarda las versiones instaladas de los paquetes.

`create-dashild` fija `@dashild/*` en el `package.json` generado a la versión del
stack con la que se publica (el campo `dashildPackages` de su propio manifiesto).
El scaffolder puede ir por delante del stack para sus propios arreglos; la app
generada conserva los paquetes publicados con los que se probó.

Las `dependencies` de una plantilla se fusionan después de ese fijado, así que
una plantilla puede sobrescribir `@dashild/*` y romper la garantía. No declares
paquetes `@dashild/*` en una plantilla.

`create-dashild` se publica con `latest` y `alpha`; la documentación usa
`pnpm create dashild@latest`.

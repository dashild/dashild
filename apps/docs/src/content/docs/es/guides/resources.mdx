title: Recursos

Un recurso es un fichero serializable. Describe la tabla, el formulario, los
filtros, la navegación y las acciones de un modelo Prisma. No hay páginas que
generar ni ficheros que mantener en sincronía.

```ts
// src/dashild/resources/customer.ts
import { defineResource } from "@dashild/core";

export const customerResource = defineResource({
  model: "Customer",
  navigation: {
    label: "Customers",
    slug: "customers",
    group: "Sales",
    icon: "users",
  },
  table: {
    searchable: ["name", "email"],
    columns: [
      { field: "name", sortable: true },
      { field: "email" },
      {
        field: "status",
        format: "badge",
        tone: { ACTIVE: "green", LEAD: "danger" },
      },
    ],
    filters: [{ field: "status", type: "enum" }],
  },
  form: {
    fields: [
      { field: "name", type: "text", rules: { required: true } },
      { field: "email", type: "email", rules: { required: true } },
      { field: "status", type: "enum" },
    ],
  },
  policy: { scope: "organization" },
});
```

`dashild make:resource Customer` genera este fichero a partir de los metadatos
de Prisma y lo registra en `panel.ts` y `policies.ts`. El fichero es write-once:
el comando nunca sobrescribe tus ediciones.

## Navegación

`label` es la etiqueta de la barra lateral, `slug` es el segmento de URL bajo la
ruta del panel y `group` agrupa recursos en la barra. `icon` lo resuelve el shell
(`users`, `user`, `building`, `organization`, `file-text`, `settings`,
`database`, `folder`, `chart`, `layout-dashboard`, `package`, `shopping-cart`,
`tag`, `calendar`, `mail`, `briefcase`, `credit-card`, `truck`, `layers`), y la
app puede añadir los suyos en `src/dashild/icons.tsx`.

## Tabla

- `columns`: field, label opcional, `sortable`, `format`, `cell`, `display` y
  `tone`.
- `searchable`: campos que usa el buscador. La paginación, el orden y los
  filtros se ejecutan en el servidor.
- `filters`: `boolean`, `enum`, `relation`, `text`, `number` o `date`.
- `pageSize`: tamaño de página opcional.
- `actions`: acciones de cabecera o de fila (ver abajo).

`tone` acepta `accent`, `green`, `muted` o `danger`; cualquier otro valor
renderiza el badge outline por defecto.

`format` acepta `badge`, `number`, `currency`, `date`, `datetime`, `json` o
`text`. Los booleanos y enums usan `badge` por defecto. `number` y `currency`
formatean con el locale del panel; para dinero `Decimal` usa
`format: "currency", currency: "EUR"`. Las listas escalares (`String[]`,
`Int[]`...) se muestran y editan como un array JSON. `cell` apunta a un
componente registrado con `registerCell` (ver
[Personalización](/es/guides/customization/)).

Para relaciones, pon el nombre de la relación en `field` y el campo legible en
`display`:

```ts
{ field: "organization", display: "name" }
```

### Filtros

Todavía no hay controles de filtro en el shell. La página de listado los lee de
la query string y los aplica en el servidor, así que puedes enlazar a una tabla
filtrada (`?status=ACTIVE`) o construir tus propios controles. Los filtros
`relation` solo soportan relaciones many-to-one; `enum` y `text` comparan
valores exactos.

## Formulario

Los campos usan el tipo de Prisma por defecto. `rules` añade `required`, `min`,
`max` o un `pattern`; `component` apunta a un campo registrado con
`registerField`; `default` fija un valor inicial.

```ts
form: {
  fields: [
    { field: "name", type: "text", rules: { required: true, max: 120 } },
    { field: "email", type: "email", component: "email" },
    { field: "notes", type: "textarea" },
    { field: "tags", type: "relation", relation: "tags", multiple: true, display: "name" },
  ],
}
```

Los campos `Bytes` muestran un selector de fichero y se envían en base64.
`createdAt` y `deletedAt` aparecen en la tabla; `updatedAt`, `id` y las claves
foráneas de relación se omiten de la tabla y del formulario. `make:resource`
tampoco incluye los campos de auditoría (`createdAt`, `updatedAt`, `deletedAt`)
en el formulario.

## Relaciones

- **o2m** (uno a muchos): la página de detalle del padre muestra un
  `RelationManager` con los hijos. Crear y editar están disponibles; borrar solo
  cuando el recurso hijo lo permite, y desasociar solo si la clave foránea es
  opcional.
- **m2m** (muchos a muchos): el detalle permite asociar y desasociar cuando el
  recurso hijo lo permite, y el formulario puede usar `type: "relation"` con
  `multiple: true`.

El modelo hijo necesita su propio recurso en `panel.resources`, y el manager
necesita `relationAction` cableada en la ruta (el scaffold lo hace). Sin filas o
sin esa acción, el manager no se renderiza.

## Acciones

Las acciones se declaran en el recurso y se resuelven en el servidor:

```ts
table: {
  actions: [{ name: "export", label: "Export", placement: "header" }],
}
```

```ts
// src/dashild/actions/index.ts
import type { ActionHandler, CurrentUser } from "@dashild/core";

export const resourceActions: Record<
  string,
  Record<string, ActionHandler<CurrentUser>>
> = {
  Customer: {
    export: async ({ db, organizationId }) => {
      // `db` es el cliente Prisma scopeado, tipado como `unknown` en core.
      const client = db as typeof prisma;
      return { ok: true, message: "Export started" };
    },
  },
};
```

Declarar `table.actions` **sustituye** las acciones integradas de crear, ver,
editar y borrar; inclúyelas tú si las sigues queriendo. Las acciones de
formulario funcionan igual.

Una acción puede declarar `requires` (validado contra las políticas), `confirm`,
`variant`, `placement` (`header` o `row`) y `href` para acciones de enlace.
`variant` estiliza el botón y la confirmación, no el ítem del desplegable de
fila.

## Doctor

```bash
pnpm dashild doctor
```

Parsea los recursos con Babel (sin importar Next) y comprueba modelos, columnas,
filtros, campos de formulario, relaciones, `policy`, la entrada de
`policies.ts`, handlers de acciones, predicados `requires` y slugs duplicados.
Siempre indica el fichero; la línea se incluye cuando el problema viene de un
nodo del recurso. Algunos hallazgos son avisos y no afectan al código de salida.
Sale con código 1 ante errores, y también cuando no encuentra ningún recurso. No
valida detalles de presentación como `navigation.label`, `format`, `tone` o
`placement`.

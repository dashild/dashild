La tabla siguiente enumera el ejemplo documentado y mantenido actualmente. Es
una aplicación ejecutable, no un fixture, y vive fuera del workspace de pnpm
para instalar los paquetes `@dashild/*` publicados igual que la app de un
usuario.

| Ejemplo | Qué muestra |
| --- | --- |
| [Clínica veterinaria](/es/examples/vet-clinic/) | Multi-tenencia, roles, relaciones, acciones, filtros y una celda custom |
| [Tienda](/es/examples/shop/) | Dinero con Decimal, stock, pedidos, relation managers y acciones de estado |

El ejemplo de la clínica veterinaria incluye:

- Base de datos SQLite sembrada y cuentas de demo.
- Un fichero de recurso por modelo, con políticas y handlers de acciones.
- Un README con los comandos y qué probar en la UI.

## Ejecutar un ejemplo

```bash
cd examples/vet-clinic
pnpm install
pnpm prisma migrate deploy
pnpm db:seed
pnpm dev
```

El panel está en `/admin`. Las credenciales de demo aparecen en el
[tutorial](/es/examples/vet-clinic/).

## Por qué están fuera del workspace

Un ejemplo dentro del monorepo resolvería `workspace:*` y escondería los fallos
que importan en una instalación real: exports que faltan, componentes de cliente
dentro de `node_modules`, Tailwind sin escanear el build del paquete o un alias
que solo existe en el workspace. Estas apps instalan los tarballs publicados, así
que prueban lo que recibe el usuario.
